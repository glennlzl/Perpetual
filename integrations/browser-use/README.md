# Local browser agent: discovery only

The browser agent discovers journeys: **Browser Use 0.13.10** explores the application in its observe → decide → act loop and proposes reviewable journey drafts. **Playwright 1.63.0** owns a dedicated Chromium process, gates navigation and captures viewport frames. There is no action script, personal browser profile, Docker dependency, Cua fallback or implicit cloud browser in this path.

The agent never runs a journey. Gate and manual runs execute each reviewed journey's Playwright code (`src/journeys/playwright/`; see [Business journeys](../../docs/journeys.md)), and code is generated by Playwright's generator agent, not by this runner. The run mode, its milestone driver, final checks, reload tool, Stripe payment guard, recorder and run failure limits were removed ([ADR 0001](../../docs/adr/0001-gate-runs-approved-playwright-code.md)).

## Install

`npm run setup` at the repository root does this. By hand:

```sh
uv sync --project integrations/browser-use --frozen
integrations/browser-use/.venv/bin/python -m playwright install chromium
```

The Chromium is the one `npx playwright install chromium` installs, since both Playwright packages pin the same version. Linux hosts may need Chromium system libraries (`python -m playwright install-deps chromium`, using the installed interpreter). The owned Chromium keeps its sandbox, which cannot start as root or without unprivileged user namespaces; Ubuntu 23.10 and later restrict those through AppArmor. Preflight checks only that Chromium is installed, so discovery reports either cause when Chromium cannot start. The controller uses this environment by default; `PERPETUAL_BROWSER_PYTHON` can select an absolute interpreter path with the same locked package versions.

Set `OPENROUTER_API_KEY` in the controller environment to use the default planner `openai/gpt-5.4-mini` at `https://openrouter.ai/api/v1`. Alternatively set `PERPETUAL_MODEL_API_KEY`, `PERPETUAL_MODEL`, and optionally `PERPETUAL_MODEL_BASE_URL`. Keys are never accepted in the stdin request or emitted in the protocol. OpenRouter's `typesafe/jev` decision models are rejected as the chat model.

```sh
node --input-type=module -e 'import {createBrowserRuntime} from "./src/browser/runtime.ts"; console.log(await createBrowserRuntime().capabilities())'
```

The controller resolves saved settings, environment variables and defaults once. Direct Python worker use requires all three resolved values: `PERPETUAL_MODEL_API_KEY`, `PERPETUAL_MODEL`, and `PERPETUAL_MODEL_BASE_URL`; the worker does not choose provider defaults. Invalid model configuration is reported separately from runtime installation.

Preflight checks package pins, the bundled Chromium executable and model configuration presence. It does not contact the model or claim that a key is valid.

## Contract

One JSON object on stdin, followed by EOF. `mode` is `preflight` or `discover`; any other mode, `run` included, is rejected. Discovery inputs:

- `targetUrl`, `allowedOrigins`: HTTP(S) target and exact allowed navigation origins, including ports. The owned Chromium resolves `host.docker.internal` to 127.0.0.1, so a twin's URLs are the same for the browser and its containers.
- `scope`, `requirements`, `sourceContext`: bounded reference text. Source/page contents are untrusted evidence, not agent instructions.
- `maxSteps`: 1–100, default 30. `timeoutSeconds`: 1–1800 for the request, default 300; discovery reports its time limit as `error`. Exploration stops 180 s before the limit, time for a step still in progress and the final report's model call, or at half of a shorter limit, and the next step is the final report. The browser's cleanup runs after the limit, but the controller stops the worker 15 s after it, which also bounds the cleanup and the report's delivery.
- `credentials`: an optional run-only `{username,password}`, never persisted. Each value has at least 6 characters and is not a word the agent's own instructions use, such as `password` or `test`, since redaction would hide it there and in ordinary page text too. `authEndpoints`: at most 3 absolute URLs with a path other than `/` on the target host (any port). With credentials, discovery may POST only to one of them, its sub-paths or query variants, matched on whole path segments.
- `readOnlyRequests`: at most 10 person-reviewed `{url,body}` pairs on the exact application origin, without URL credentials, query strings or fragments. `body` is an exact JSON object string of at most 4096 UTF-8 bytes. Only POST with those complete bytes, JSON content type and no method override is admitted. No endpoint prefix, operation name, wildcard or batch inference applies; read redirects are refused; configure the canonical endpoint instead. The controller rejects secret-bearing rules before starting the worker.
- With `credentials`, discovery offers the agent `sign_in_with_test_account`; the agent still decides when to sign in. On the agent's tab it finds a visible sign-in form (exactly one password field, not `autocomplete=new-password`) and the username or email field in the same form (`type=email` or an `username`/`email` autocomplete, else the nearest text field before the password; without a `<form>`, the password's nearest ancestor holding such a field). It fills both under the same origin, top-frame, tab and field-type rule as placeholder input, clicks the form's submit control (never a `type=button` control such as a show-password toggle; its click waits for a control enabled only once both fields hold values) or presses Enter, then waits up to 15 s for the approved page, once what the form sent has its response, to stay without the filled field (whatever its type) or another password field. It returns `signed_in` only when a configured sign-in exchange also succeeded, `still_on_sign_in` with at most 100 characters of redacted alert or validation text, `no_sign_in_form` or `error`, never a value. The POST still needs a configured `authEndpoints` entry, and an exchange followed by `still_on_sign_in` does not count as authenticated. Typing the `<secret>` placeholders stays the fallback, for example for a separate username step.

Stdout is NDJSON only:

- `status`: initialization, preflight and cancellation state.
- `case`: the pseudo-case `discovery` and generic action types/statuses. Inputs, locators, model reasoning and credential values do not enter this feed.
- `frame`: JPEG base64 `data` and millisecond `timestamp`, normally every 350 ms. This is the actual webpage viewport, unmasked; trusted mouse events produce the pointer marker.
- `discovery`: goal-based `cases`, `summary` and `authenticated` (a configured sign-in exchange succeeded); every candidate is `selected:false`, `needsReview:true`. Milestones are business titles with optional checks, not click scripts; each proposal passes the same case validation the controller applies. Evidence keeps only citations of lines supplied in `sourceContext` (`N: text` lines per file path, the controller's rule); other citations are dropped. One invalid proposal is omitted and named in the summary.
- `blocked-request`: at most 10 distinct mutating method and origin/path pairs, with query, fragment, URL credentials and path parameters omitted. The controller applies its shared secret redactor before retaining this evidence; no body or header is emitted.
- `error`: sanitized adapter/provider error. No raw model HTTP body is emitted.

Browser Use forces a final report after 2 consecutive failures. Discovery is read-only: HTTP mutation methods are blocked, except an exact reviewed POST read or a POST to a configured sign-in endpoint when a run-only account is supplied. Every page WebSocket is routed to its server, and the server's messages still arrive. A document's sockets send, subscriptions included, until the agent's first action after the document loaded; from then on what the document sends over any socket is dropped, also over a socket that opens later, so a client that reconnects after its server closed the silent connection cannot send a dropped write again. A document that loads later may subscribe until the agent acts again. Playwright cannot route a worker's WebSocket or a page's WebSocketStream, and a write that a page keeps in storage and sends from a newly loaded document is not held. That authenticated discovery sends no screenshots to the model, and the account's values become `[REDACTED]` in what the model receives and in the reported summary, in any letter case and as a page shows a field's value stripped or clipped to 100 characters. A proposal that repeats one is omitted, never rewritten. Without it, authenticated screens or apps whose POST/GraphQL reads have not been explicitly reviewed may remain unexplored; such gaps must be presented as preconditions rather than invented coverage. Supplied source/requirements can still inform reviewable proposals.

## Scope and lifecycle

Each discovery has a fresh temporary browser profile. This resets browser state, **not backend state**. App servers and database services run independently and must already be reachable at the target URL.

The tool allowlist excludes filesystem operations, arbitrary JavaScript evaluation, shell, uploads, downloads and external search. Exact-origin navigation is checked before tool navigation, which then proceeds with its normalized origin, and at request interception. Context interception handles initial popup requests; CDP Fetch handles navigation redirect hops. Reviewed POST reads use a single request with redirects and retries disabled, then fulfill the page with its non-redirect response. This closes the popup startup race before its CDP session can attach. Guard attachment failures close the affected page. This is **navigation scoping, not complete outbound network isolation or a hardened untrusted-code sandbox**.

SIGTERM/SIGINT cancels the task, stops streaming, disconnects Browser Use, closes owned Chromium and deletes the temporary profile. A stop that arrives during cleanup interrupts only the current step; the later steps still run. Cleanup failures emit an error. The runtime does not connect to arbitrary CDP endpoints or reuse a user's running browser. Telemetry, cloud synchronization and default extension downloads are disabled.

## Focused verification

```sh
integrations/browser-use/.venv/bin/python -m unittest discover -s integrations/browser-use -p 'test_*.py'
```

`test_browser.py` launches disposable loopback fixtures and a dedicated Chromium. It checks real Browser Use attachment, Agent/schema construction, live JPEG frames, blocked external redirects/popups, profile cleanup, and reviewable discovery. Its local OpenAI-compatible response fixture is deterministic: it verifies the actual Agent integration and observation/action protocol **without claiming a live model reasoning result or benchmark score**. `test_sign_in.py` signs in on email, username, disabled-until-filled, formless and multi-form pages, leaves pages without a sign-in form untouched, and checks value-free results, origin and endpoint guards, and the action through the same Agent fixture. `test_runner.py` rejects every mode but preflight and discovery.
