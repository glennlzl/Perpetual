# 4. Review application callback aliases independently of published ports

A rebuilt local Compose application can return from an external provider through a different published port, while fixed external origins correctly remain fixed. A person therefore reviews an exact application id and `localhost` or `127.0.0.1` alias; the controller resolves it only for the unambiguous selected application of the same stage's ready, owned twin, and supplies that exact HTTP origin to code authoring and normal/control runs. The scope, application id and alias bind verification and approval, while the environment id and port do not: rebuilding the same application preserves approval, changed bindings need three passes, a caught control and explicit approval, and missing ownership or a substituted target blocks admission without erasing review history.

Status: accepted. Fixed sites are neither inferred as bindings nor rewritten; fixed sites and bindings together remain limited to ten entries. Discovery stays on application origins, active verification captures one configuration/environment/origin set under its lease, and restart starts no work. Remote aliases, wildcard hosts, HTTPS twins and socket permissions are outside this decision.
