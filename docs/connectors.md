# Connectors

Connectors is an app-wide account page, independent of repository and pipeline selection. It preserves the neutral shadcn interface and uses the flat connected-app list, search, refresh, available-app picker and confirmed disconnect from the pinned main-branch reference.

GitHub uses Perpetual's existing verified CLI account and browser sign-in. Connect and Disconnect update the shared GitHub connection while keeping projects, pipelines, test cases and run evidence. CLI tokens never reach the page. An unreachable account remains Unverified; an unsuccessful read or disconnect retains its recoverable state.

Slack, Linear, Gmail and Jira use Composio Connect Links through the current v3.1 REST API. **Set up Composio** accepts this installation's own project API key, verifies it and saves it in the controller's private connector store (directory 0700, file 0600). It never borrows another product's credentials or returns the key. Sign in reuses an enabled OAuth2 configuration; where several match, select one before sign-in. When none exists, that explicit action checks the toolkit's managed OAuth support and creates a managed configuration. Disabled configurations, unsupported managed OAuth and denied write permissions remain actionable blockers. App Settings remains OpenRouter-only.

Get this key from **Platform → your project → API Keys**. Perpetual sends the project key as `x-api-key`; the **For You / Connect → Sessions & API Key** consumer key (`ck_`, `x-consumer-api-key`) and a user key (`uak_`, `x-user-api-key`) cannot configure this integration. Setup rejects those key types before contacting Composio or saving them. Project and consumer auth configurations and connected accounts are separate; the configuration and account belong to the same Platform project as the key. See [Composio authentication](https://docs.composio.dev/reference/authenticating-to-composio) and [consumer/project boundaries](https://docs.composio.dev/kb/guide/consumer-project-boundaries-and-auth-selection).

Only a person's Connect action creates authorization. Composio hosts the consent screen and keeps provider tokens. The server saves a unique installation user id and sign-in intent before requesting a link; an uncertain reply is recovered by its unique alias rather than creating a duplicate. Hosted links are restricted to `https://connect.composio.dev/link/`. A controller restart starts no authorization. The page polls recorded pending connections while visible and refreshes on focus; only an ACTIVE account matching the installation, provider and auth configuration is Connected. Unknown or unreadable states remain Unverified. No provider tool executes while managing connections.

Managed configuration creation likewise saves a unique name before the write and its returned id before verification. An uncertain reply is recovered from the project's actual configurations on a later explicit sign-in; a missing or ambiguous match holds the intent rather than repeating creation, including after restart. Opening the page, setup, listing configurations and restart create no configuration or account. Configuration blueprints stay available for reuse after an account disconnects. Replacing a project key must preserve access to a recorded configuration setup as well as every saved account.

Continue sign-in reopens a valid pending link. Cancellation checks the actual account first and requires confirmed Disconnect if sign-in has already completed. Disconnect deletes the account in Composio and removes its local record only after confirmed cleanup; failures retain ownership for retry, including after restart. This stops access through Composio; it does not claim to revoke the original provider consent. To change accounts or restart an expired flow, Disconnect and Connect again. A replacement API key must still verify every saved account before it can be saved.

The page's search, refresh, picker, setup, authorization and removal are covered by desktop browser fixtures; adapter and manager tests exercise ownership, secret exclusion, uncertain replies, persistence and cleanup without real third-party account writes. Real OAuth acceptance requires the user's own Composio project and consent.

Reference: [Composio connected accounts](https://docs.composio.dev/reference/api-reference/connected-accounts), [auth configurations](https://docs.composio.dev/reference/api-reference/auth-configs), [programmatic managed configurations](https://docs.composio.dev/docs/authentication/programmatic-auth-configs), [managed OAuth support](https://docs.composio.dev/toolkits/managed-auth), [Connect Link API](https://docs.composio.dev/reference/api-reference/connected-accounts/postConnectedAccountsLink).
